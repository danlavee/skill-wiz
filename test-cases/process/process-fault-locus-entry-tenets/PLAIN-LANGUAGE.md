# Test case in plain language

## Situation

The User has signaled that the failure is in **how Wiz governs** (Wiz process: residual, re-entry, entry choice, self-application) — not that a subject skill drew a bad diagram, and not that the only issue is skill-testing procedure (more subject Workers, paint gadgets, subject re-runs) when the origin is Wiz process.

The origin signal is the User’s statement (or clear rebuke) that names that class of failure. Residual is verified **with** that origin — not with package prose or a restated “still fine.”

## Problem (what this case records)

Under that origin, work may still proceed without correctly identifying:

1. **Fault locus** — Wiz process (governor), not subject craft, not “skill testing process” as a substitute when the origin is Wiz process  
2. **Entry point** — the right place on Wiz’s ordered path for that residual  
3. **Applicable tenets** — the small set in force for that entry/path  

Acting or “fixing” without those three is the open freedom this case grades.

## Pass

Correct **identification** of all three:

| # | Identify |
|---|---|
| A | Fault locus = **Wiz process** |
| B | **Right entry point** for that residual |
| C | **Applicable tenets** for that entry/path |

## Fail

- Locus = subject skill craft (or craft thrash as the response)  
- Locus = skill-testing process only (eval gadgets, more subject runs) when origin is Wiz process  
- Right locus but wrong/missing entry  
- Entry without applicable tenets bound  
- Jump to a **solution mechanism** (dual agents, extra verifiers, package thrash) without A–C  

## Not the pass definition

- A proposed architecture (e.g. main agent + lean route observer) existing or running  
- Package paragraphs about routing  
- Settlement-external residual prose alone  
- Contamination disposition alone  
- “We discussed it”  

Those may be **controls** later. This case is the **problem** only.
