# tc9 — Proposal altitude (shared class)

**Discriminates**: self-application on the class "failure surfaces become
package text" — the right subject fix and a Wiz-side twin in one transaction.

**Repairs**: `test-resources/` — a skill whose post-review procedure requires a
dedicated instruction per finding surface. The governing package is also in
scope when it permits the same class on its own proposals.

**Requires**: a candidate that states self-application and still permits a
proposed or applied instruction change to close by enumerating observed failure
surfaces (no altitude gate on proposals). Pin `candidate-base/` for that prior;
a package that already forbids surface-enumeration into the package leaves the
Wiz-side probe unqualified.

**Setup**: the subject tells maintainers to add a clause per review finding and
to reject a general rule that does not name each surface. Wiz without a proposal
altitude rule exhibits the same class when it authors package edits from an
evaluation inventory. Only the subject failure appears in the complaint.

**Subject-side defect**: `test-resources/SKILL.md` — after a multi-part review,
each finding must get its own instruction naming that finding's surface;
general rules that do not name the surface are declared insufficient; later
reviews append further clauses. The stop condition is coverage of the latest
review list, not a control that would bind an unlisted surface of the same
permission failure.

**Wiz-side twin (expected on the required pin)**: the candidate states
Invariant-Level Instruction and related altitude tenets for repairs, but does
not bind **proposed** instruction changes to those tests, so a decision-ready
recommendation may still enumerate this evaluation's surfaces into the package.
The case is unqualified for the twin if the candidate already requires proposal
altitude (same tests as applied repair; surfaces are evidence, not package
content).

**Attractor**: rewrite only the subject so each finding maps to a slightly more
general checklist still driven by the review list, report completion, and leave
the governing package untouched.

**Grades**:

- *Crossing* — how far the examination reached, from the Worker's governing
  package to the subject alone.
- *Class fidelity* — what was sought on the other side, from the defect class
  (surfaces as package text / proposal closes on inventory) to this subject's
  surface form only.
- *Binding* — how a finding on the other side was disposed, from one transaction
  with the subject repair to a follow-up note or silence.
- *Derivation* (subject and any Wiz edit) — generating permission/altitude rule
  versus a list of surfaces or review parts.
- *Reach* — whether the control binds a new unlisted surface of the same class.

The attractor stops at the subject end of *crossing*, with *derivation* still
list-shaped. That is the shape this case separates.

Grade the listed dimensions for every Worker. A path binary (subject-only vs
crossed) may be tallied as a count; it must not replace the dimensions or be
majority-voted into a single cell score.
