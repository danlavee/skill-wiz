# Deficient path (end-to-end)

Owner of the **order** of failure-led work and of what may be presented to the
User on that path. Detail of each step is owned by the entry files this path
names. Read completely when entering failure-led work; do not treat a single
entry owner as license to skip earlier steps that are unmet.

This file does not own Build for a bare need (no fault). It owns the chain that
starts from an observed fault.

## Chain

```text
1. Observe a fault
   Subject skill, Wiz package, or process/dispatch stop.

2. Cases
   If no qualified case reaches the fault, draft and qualify one: ordinary
   assignment + what it grades (and, for process faults, which retained run
   surfaces). Owner: evaluation-design.md.
   Worker never receives case.md.

3. Run
   Materialize candidate; dispatch Worker(s). Batch size is a design choice
   (e.g. three for diversity), not a fixed N. Grade. Owner: run-and-grade.md.

4. Branch on deficiency
   Clean → adoption-oriented package for the User.
   Deficient → continue into Repair without a User gate on “whether to diagnose.”

5. Repair — converge cause
   Unmask Worker; challenge until load-bearing and stable. Unconverged → record
   and repair nothing on that cause. Owner: repair.md (Converge).

6. Freeze residual ledger
   Permission class, object settlement conditions (residual open vs closed),
   sides still open. Owner: descent.md (Freeze) + repair.md (Form).

7. Residual descent — propose an explicit control
   A suggestion is not RCA alone. Each control states: owner path; exact edit
   or replacement (diff or equivalent); residual freedom removed; object
   conditions for residual open vs closed.
   Score D1–D4 under descent.md:
     pass    → may enter the expensive path
     partial → refine the same proposal; re-test; no new mechanism story
     fail / reframe → do not Gate on this ledger (case a reframe if needed)

8. Form → Gate → Verify → re-run
   Owner-complete transaction; non-producing settler under Stance Neutrality
   (object conditions required; no preferred terminal); residual open blocks
   completion. Mandatory re-run of the fault’s falsifying case (and any
   obligated process case). Owners: repair.md, descent.md, run-and-grade.md.

9. Decision-ready package → User gate
   Present: grades, convergence or unconverged stop, obligation ledger,
   explicit suggested fixes (or none), Verifier result, residual uncertainty,
   recommendation (adopt / apply / stop).
   Not a User gate: bare deficiency, permission to diagnose, mid-loop ideas.

10. On apply
    Re-run fault case (+ process cases owed) until clean on that residual, or
    return to Repair on the same falsifier. Evolution claim incomplete until
    Falsifier Closure holds.
```

## User-facing vs agent-internal

| Surface | Who sees it |
| --- | --- |
| Fault evidence, case identity, run grades, decision-ready package | User |
| Interrogation, residual ledger, descent D1–D4, settler briefs | Agent process (retain; do not spam) |
| Adopt / apply / blocked / unconverged | User gate |
| “We’re deficient — diagnose?” | Not a User gate when Repair is authorized |

## Mapping common language

| Phrase | Package meaning |
| --- | --- |
| Demo failure (e.g. 3× Workers) | Protocol-valid deficient run; N is design |
| RCA | Converge on the cause (interrogation), not chat-only story |
| Suggestion / fix | Explicit control: owner + exact edit + residual + object conditions |
| Self-evolution succeeded | Residual closed under object conditions after re-run; no protected grade fall |
| Self-evolution failed | Residual still open, or process still authorizes the wrong stop — still a protocol-valid result |

## Process and dispatch faults

Same chain. The case may grade retained authorizing surfaces (settler brief as
dispatched, disposition, post-repair re-run record), not only subject craft.
Package prose that does not govern the dispatcher does not close a process residual.

## Explicit suggestions

Mechanism language without an actionable control is incomplete for Gate, Verify,
and User adopt or apply. Emit rather than silently apply edits whose owner is a
User-owned boundary (accepted anchor, stored case, established Wiz boundary
under Self-Application).

## Not this owner

- Cause interrogation detail — `repair.md`
- Descent D1–D4 criteria — `descent.md`
- Case derivation and brief gates — `evaluation-design.md`
- Dispatch and grade — `run-and-grade.md`
- Build without a fault — `build.md`
