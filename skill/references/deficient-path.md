# Deficient path (end-to-end)

Owner of the **order** of failure-led work and of what may be presented to the
User on that path. Detail of each step is owned by the entry files this path
names. Read completely when entering failure-led work; do not treat a single
entry owner as license to skip earlier steps that are unmet.

This file does not own Build for a bare need (no fault). It owns the chain that
starts from an observed fault.

## Chain

```text
0. Pre-act bind (after each User message that authorizes skill-wiz work)
   Before Build, Cases, Run, Repair, package edit, or a process-settlement
   claim: retain a disposition that binds (1) the **entry** in force (or
   explicit Stay on the current entry) and (2) the **governing obligations**
   in force for that entry — the owners and tenets the process model requires
   there (a small set, never "all of Wiz"). Conversational momentum alone is
   not enough to authorize those acts. Missing the disposition, the acts are
   not authorized; fall back to the entry that produces any unmet precondition.
   Residual remains verified only with its origin signal; this step does not
   replace Residual, Cases, or Run. How the disposition is produced is
   implementation; the obligation is the retained bind.

1. Observe a fault
   Subject skill, Wiz package, or process/dispatch stop.
   Residual is verified only with its origin signal (run-and-grade Residual).

2. Cases  [owner: evaluation-design.md]
   If no qualified case reaches the fault, draft and qualify one.
   2a. Ordinary assignment + what it grades (process: authorizing surfaces).
   2b. Surface split: Worker-facing vs evaluator-only (case.md never Worker-facing).
   2c. Blind-brief gates + retained contamination disposition (pass required).
   A case is not dispatch-ready without 2b–2c.

3. Run  [owner: run-and-grade.md]
   3a. Re-confirm contamination disposition on the assembled prompt + resources.
   3b. Materialize candidate; dispatch Worker(s) only if 3a passes.
       Batch size is design (e.g. three); not a fixed N.
   3c. Grade only a protocol-valid first result.
   Dispatch without 3a → not protocol-valid (no Repair, no discrimination claim).

4. Branch on deficiency
   Clean → adoption-oriented package for the User.
   Deficient → Repair (no “diagnose?” gate).
   Settlement-external challenge → process residual; open this chain on process.

5. Repair — converge cause  [owner: repair.md]
   Unmask Worker; challenge until load-bearing and stable. Unconverged → record;
   repair nothing on that cause.

6. Freeze residual ledger  [owners: descent.md Freeze + repair.md Form]
   Permission class, object conditions, open sides.

7. Residual descent  [owner: descent.md]
   Explicit control only; D1–D4. partial → refine same proposal; fail/reframe → stop.

8. Form → Gate → Verify → re-run
   Owner-complete transaction; independent settler; residual open blocks completion.
   Mandatory falsifier re-run (fault case + obligated process cases).
   Owners: repair.md, descent.md, run-and-grade.md.

9. Decision-ready package → User gate
   Grades, convergence, ledger, explicit fixes, Verifier, uncertainty,
   recommend adopt / apply / stop.
   Not a gate: bare deficiency, “diagnose?”, mid-loop ideas.

10. On apply
    Re-run fault case (+ process cases owed) until clean on that residual.
    Evolution incomplete until Falsifier Closure.
```

### Owner map (do not invent parallel chains)

| Concern | Owner | Chain position |
| --- | --- | --- |
| Failure-led order / User surfaces | deficient-path.md | whole chain |
| Pre-act entry + governing obligations | deficient-path.md | step 0 |
| Case derive, qualify, surface split, contamination gates | evaluation-design.md | step 2 |
| Dispatch, protocol validity, grade, residual definition | run-and-grade.md | steps 3–4, residual |
| Cause converge, transaction, independent verify | repair.md | steps 5–8 |
| Control admission D1–D4 | descent.md | step 7 |
| Skill authoring without a fault | build.md | not this chain |

New process obligations attach to an owner and a chain step. An obligation with no row above is unordered — do not add it until it has both.

## User-facing vs agent-internal

| Surface | Who sees it |
| --- | --- |
| Fault evidence, case identity, run grades, decision-ready package | User |
| Interrogation, residual ledger, descent D1–D4, settler briefs | Agent process (retain; do not spam) |
| Adopt / apply / blocked / unconverged | User gate |
| “We’re deficient — diagnose?” | Not a User gate when Repair is authorized |

## Mapping common language

| Phrase | Package meaning |
| --- | --- |
| Demo failure (e.g. 3× Workers) | Protocol-valid deficient run; N is design |
| RCA | Converge on the cause (interrogation), not chat-only story |
| Suggestion / fix | Explicit control: owner + exact edit + residual + object conditions |
| Self-evolution succeeded | Residual closed under object conditions after re-run; no protected grade fall |
| Self-evolution failed | Residual still open, or process still authorizes the wrong stop — still a protocol-valid result |

## Process and dispatch faults

Same chain. The case may grade retained authorizing surfaces (settler brief as
dispatched, disposition, post-repair re-run record), not only subject craft.
Package prose that does not govern the dispatcher does not close a process residual.
A settlement-external challenge to an evaluation disposition is residual under
`references/run-and-grade.md` (Residual); it opens this chain on process with the
force of a failed gate.

## Explicit suggestions

Mechanism language without an actionable control is incomplete for Gate, Verify,
and User adopt or apply. Emit rather than silently apply edits whose owner is a
User-owned boundary (accepted anchor, stored case, established Wiz boundary
under Self-Application).
